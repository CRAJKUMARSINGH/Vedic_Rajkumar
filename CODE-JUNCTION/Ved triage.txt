# Robotic review: can your app answer this query?

**Short answer: no. Not as written, not confidently, and today it would answer a *different* question than the one asked.**

Your user handed you a **natal chart summary** (`Venus in 12th`, `Lagna 1st with Sun+Jupiter+Gulika`, `Moon in 4th`) and then asked for a **future prediction**. That is natal-astrology input with a prashna-shaped question. Your app has no lane for it.

| Check | Result |
|---|---|
| Placement text parsed? | No — no house/planet parser exists anywhere in `src/` |
| Chart recomputed from placements? | No — engine needs DOB/TOB/place or a question moment |
| Topic resolved? | No — "what future can you predict" has zero keywords, scores 0, defaults to house 1 |
| Would it produce a verdict anyway? | Yes — a confident-looking one, on the wrong chart |
| Confidence available on prashna path? | No — `PrashnaResult` has no confidence field at all |

## 2. The fix: a three-lane intake router

Never let the model improvise a natal reading off three placements — it will sound certain and be unfalsifiable. Route instead.

**Rule table (evaluated in order, first match wins):**

| Lane | Trigger | Cap | Allowed output | Forbidden |
|---|---|---|---|---|
| A `natal_full` | DOB + TOB + place | 0.85 | Full chart, dasha, transit window | — |
| B `placements_only` | ≥2 planet-in-house mentions, no birth data | 0.45 | House-based reading, strengths, remedy | Dasha, any dated window, "yogini"/varshaphal claims |
| C `prashna_now` | question moment + place, no placements | 0.75 | Horary verdict, significators, remedy | Saying it is "your chart" |
| D `insufficient` | none of the above | 0.00 | Max 2 asks | Any verdict |

`confidence = cap × topicCertainty`, where topicCertainty = 1.0 (topic found) / 0.7 (topic missing, house 1 assumed) / 0.6 (unknown planet token present). Lane B **never** prints a window — that is the single biggest honesty lever, because a house-only read cannot date anything.

**If both placements and a moment are present**, still use B but cap at 0.50 and state plainly: *"the chart cast now is not the chart you typed."* Do not blend methods silently — that is the failure mode that makes astrology apps look broken.

```ts
export type IntakeLane = 'natal_full' | 'placements_only' | 'prashna_now' | 'insufficient';

export interface PlacementMention { planet: string; house: number; raw: string }
export interface Ask { id: 'topic' | 'birth' | 'moment' | 'place'; en: string; hi: string }

export interface TriageInput {
  question: string;
  hasBirthData: boolean;
  hasMoment: boolean;
  hasPlace: boolean;
}

export interface TriageResult {
  lane: IntakeLane;
  mentions: PlacementMention[];
  unknownTokens: string[];
  topicHouse: number | null;
  confidenceCeiling: number;
  blockAnswer: boolean;
  asks: Ask[];
}

const PLANETS = [
  'sun','moon','mars','mercury','jupiter','venus','saturn','rahu','ketu','gulika','lagna','ascendant',
] as const;

// Planets the engine can actually score. Gulika is context-only.
const SCORABLE = new Set(['sun','moon','mars','mercury','jupiter','venus','saturn','rahu','ketu']);

const HOUSE_PATTERNS = [
  /\b(\d{1,2})(?:st|nd|rd|th)\s*(?:house|bhava|bhaav)\b/gi,
  /\bhouse\s*(?:no\.?\s*)?(\d{1,2})\b/gi,
];

function clampHouse(n: number): number | null {
  return Number.isInteger(n) && n >= 1 && n <= 12 ? n : null;
}

export function parsePlacements(text: string): { mentions: PlacementMention[]; unknownTokens: string[] } {
  const mentions: PlacementMention[] = [];
  const unknownTokens: string[] = [];

  const clauses = text.split(/[,;.\n]|[+&]|\band\b/i);

  for (const clause of clauses) {
    const lower = clause.toLowerCase();

    const planets: string[] = [];
    for (const p of PLANETS) {
      if (new RegExp(`\\b${p}\\b`, 'i').test(lower)) planets.push(p);
    }
    if (planets.length === 0) continue;

    const houses: number[] = [];
    for (const re of HOUSE_PATTERNS) {
      re.lastIndex = 0;
      let m: RegExpExecArray | null;
      while ((m = re.exec(lower)) !== null) {
        const h = clampHouse(parseInt(m[1], 10));
        if (h !== null && !houses.includes(h)) houses.push(h);
      }
    }
    if (houses.length === 0) continue;

    for (const planet of planets) {
      if (!SCORABLE.has(planet) && planet !== 'lagna' && planet !== 'ascendant') {
        if (!unknownTokens.includes(planet)) unknownTokens.push(planet);
      }
      for (const house of houses) {
        mentions.push({ planet, house, raw: clause.trim().slice(0, 80) });
      }
    }
  }

  return { mentions, unknownTokens };
}

const ASK = {
  topic: {
    id: 'topic' as const,
    en: 'One word is enough — career, marriage, money, health, or property?',
    hi: 'एक शब्द पर्याप्त है — नौकरी, विवाह, धन, स्वास्थ्य या संपत्ति?',
  },
  birth: {
    id: 'birth' as const,
    en: 'For a reading off your own chart I need birth date, exact time, and city.',
    hi: 'आपकी अपनी कुंडली से पढ़ने के लिए जन्म तिथि, सटीक समय और नगर चाहिए।',
  },
  moment: {
    id: 'moment' as const,
    en: 'Or ask it as a Prashna: confirm the moment and city of the question.',
    hi: 'या इसे प्रश्न रूप में पूछें: प्रश्न का समय और नगर बताएं।',
  },
  place: {
    id: 'place' as const,
    en: 'Which city are you asking from? The default is Delhi.',
    hi: 'आप किस नगर से पूछ रहे हैं? डिफ़ॉल्ट दिल्ली है।',
  },
};

export function triage(
  input: TriageInput,
  classify: (q: string) => number | null,
): TriageResult {
  const { mentions, unknownTokens } = parsePlacements(input.question);
  const topicHouse = classify(input.question);

  const base = { mentions, unknownTokens, topicHouse };
  const topicCertainty = topicHouse === null ? 0.7 : 1;
  const unknownPenalty = unknownTokens.length > 0 ? 0.6 : 1;

  if (input.hasBirthData) {
    const asks: Ask[] = [];
    if (!input.hasPlace) asks.push(ASK.place);
    return {
      ...base,
      lane: 'natal_full',
      confidenceCeiling: 0.85 * topicCertainty * unknownPenalty,
      blockAnswer: false,
      asks,
    };
  }

  if (mentions.length >= 2) {
    const asks: Ask[] = [];
    if (topicHouse === null) asks.push(ASK.topic);
    asks.push(ASK.birth);
    return {
      ...base,
      lane: 'placements_only',
      confidenceCeiling: (input.hasMoment ? 0.5 : 0.45) * topicCertainty * unknownPenalty,
      blockAnswer: false,
      asks: asks.slice(0, 2),
    };
  }

  if (input.hasMoment) {
    const asks: Ask[] = [];
    if (topicHouse === null) asks.push(ASK.topic);
    if (!input.hasPlace) asks.push(ASK.place);
    return {
      ...base,
      lane: 'prashna_now',
      confidenceCeiling: 0.75 * topicCertainty,
      blockAnswer: false,
      asks: asks.slice(0, 2),
    };
  }

  return {
    ...base,
    lane: 'insufficient',
    confidenceCeiling: 0,
    blockAnswer: true,
    asks: [ASK.topic, ASK.moment].slice(0, 2),
  };
}
```

# 2. Required patch: `parsePlacements` in `src/lib/intake/triage.ts`

Replace the whole function body. Two-pass with a carried house context: segment on sentence punctuation, then walk list-tokens left to right, letting a house-bearing token set the context and a house-less token inherit it.

```ts
const SEGMENT_SPLIT = /[,;\n]|\.\s/;
const LIST_SPLIT = /[+&]|\band\b/i;
const NON_SCORING = new Set(['lagna', 'ascendant']);

function findHouses(lower: string): number[] {
  const out: number[] = [];
  for (const re of HOUSE_PATTERNS) {
    re.lastIndex = 0;
    let m: RegExpExecArray | null;
    while ((m = re.exec(lower)) !== null) {
      const h = clampHouse(parseInt(m[1], 10));
      if (h !== null && !out.includes(h)) out.push(h);
    }
  }
  return out;
}

export function parsePlacements(text: string): {
  mentions: PlacementMention[];
  unknownTokens: string[];
} {
  const mentions: PlacementMention[] = [];
  const unknownTokens: string[] = [];
  const seen = new Set<string>();
  let ctx: number[] = [];

  for (const segment of text.split(SEGMENT_SPLIT)) {
    for (const token of segment.split(LIST_SPLIT)) {
      const lower = token.toLowerCase();

      const houses = findHouses(lower);
      if (houses.length > 0) ctx = houses;

      const planets = PLANETS.filter((p) => new RegExp(`\\b${p}\\b`, 'i').test(lower));
      if (planets.length === 0 || ctx.length === 0) continue;

      for (const planet of planets) {
        if (!SCORABLE.has(planet) && !NON_SCORING.has(planet) && !unknownTokens.includes(planet)) {
          unknownTokens.push(planet);
        }
        for (const house of ctx) {
          const key = `${planet}:${house}`;
          if (seen.has(key)) continue;
          seen.add(key);
          mentions.push({ planet, house, raw: token.trim().slice(0, 80) });
        }
      }
    }
  }

  return { mentions, unknownTokens };
}
```

Known limitation to record in the file header: a house-less fragment following a *different* segment inherits the previous segment's house. `"Sun in 1st, Moon"` yields `Moon:1`. That is the intended reading and TC-06/TC-09 pin it.

# 3. Additive export: `classifyQuestionDetailed`

`classifyQuestion` returns a house and cannot distinguish "house 1 because it matched" from "house 1 because nothing matched". Expose the score, then let the old function delegate.

```ts
// src/services/questionAnalysisService.ts

export function classifyQuestionDetailed(question: string): { house: number; score: number } {
  const q = normalizeQuestion(question).toLowerCase();
  let bestHouse = 1;
  let bestScore = 0;

  for (const [houseKey, entry] of Object.entries(CATEGORY_KEYWORDS)) {
    let score = 0;
    for (const w of entry.keywords) {
      if (!q.includes(w)) continue;
      score += w.includes(' ') ? w.length * 4 : w.length * 2;
    }
    if (score > bestScore) {
      bestScore = score;
      bestHouse = Number(houseKey);
    }
  }

  return { house: bestHouse, score: bestScore };
}

export function classifyQuestion(question: string): number {
  return classifyQuestionDetailed(question).house;
}
```
